# MP157 双传感器 Mac GUI

启动实时模式（需要开发板已运行 M4 固件且 ICM20608 驱动已加载）：

```bash
./run_gui.sh
```

无开发板时使用模拟的双传感器数据检查界面（演示模式含周期性 MPU Y 饱和，可看到状态切换到 ICM 补偿）：

```bash
./run_gui.sh --demo
```

程序使用 `pytorch_env` 中的 PyQt5、NumPy 和 Matplotlib。正常模式只启动一个远程采集进程 `tools/monitor_dual_imu.py`（MPU6050 RPMsg + ICM20608 `/dev/icm20608`），通过一条 SSH 流读取双传感器数据。

## 融合状态

左侧显示 `MPU` / `融合` / `ICM 补偿` / `无效` 四种状态（颜色区分）。MPU6050 Y 轴饱和时自动切换到 ICM 补偿；ICM 超时（样本年龄 >30 ms、SPI 失败、标定缺失）时进入 `无效`，不输出融合数据并暂停轨迹积分。

标定文件默认加载 `diagnostic_logs/phase6_accel_calibration/accel_calibration.json`（旋转矩阵、ICM 加速度零偏与质量指标）；缺失时仍可采集原始数据，但融合标记为无效。

空间轨迹使用 15 维误差状态 ESKF + 零速观测（ZUPT），替代阻尼积分。每次开始采集先静止约 2 秒完成初始化。左侧 ZUPT 开关控制零速观测；α 仅用于独立陀螺姿态显示。重力补偿始终启用，已移除旧速度阻尼和 kp 控件。见 [ESKF 说明](ESKF.md)。该方法仍只用于短时间运动趋势，不能作为无漂移绝对位置。

删除过期轨迹点不会重置积分位置；停止采集后保留最后一帧。点击“清空”会立即清除曲线、轨迹及姿态图的数据，同时重置指标和积分状态。静止或无轨迹时坐标轴保留最小 2 mm 跨度，避免零范围。

### 断线自动恢复（2026-09-21）

Mac 有线 `AX88772D/en7` 已手动配置 `169.254.50.1/16`，板端仍为 `169.254.50.2`。GUI SSH 主连接绑定 en7，连接超时 3 秒，保活间隔 2 秒、最多 3 次未回应。连接退出后等待 2 秒重新建立 SSH/上传读取脚本/采集；这不是整个恢复过程固定耗时 2 秒，链路协商、地址就绪、旧连接退出和 M4 准备均可能增加时间。

自动重连会清空旧数据和 ESKF 状态，需静置约 2 秒重新初始化。短暂断线若原 TCP 会话仍存活，可能直接恢复原数据流，不一定新建连接；如果传感器时间戳出现超过 0.1 秒的间隔，现有保护也会清空重标定。

点击“停止”会取消待执行的重连，关闭窗口也会取消重连；SSH/SCP/启动脚本准备阶段支持取消，避免退出后又启动采集。配置错误也会重试，持续失败时请查看控制台并点击停止。开机启动选项勾选时，每次建立连接仍会检查/安装 M4 服务，因此验证时的恢复时间不代表所有配置下的固定时延。

实际拔插已验证：固定 IP 保留，链路恢复后约 7.8 秒自动建立新 SSH 会话并恢复 50 Hz 数据；ESKF 重新初始化，停止/关闭可取消重试，无远端采集进程残留。该时延不是保证值。完整记录见 `diagnostic_logs/network_reconnect_20260921/README.md`。
